保研工作台（UNI）—— 项目经历总结

> 个人全栈效率工具 · 低代码/云原生单页应用

> 时间：2026.10 – 2026.11　|　角色：独立开发者（产品设计 + 架构 + 开发 + 测试 + 上线）

---

一、项目一句话定位

面向保研（夏令营 / 预推免）全流程的**个人申请管理平台**：把分散在 Excel、备忘录、聊天记录里的院校信息、面试题、专业课、英语积累，统一沉淀到一个可搜索、可统计、可模拟练习的在线工作台，并支持本地离线使用。

---

二、背景与痛点

保研申请信息高度分散、时间线长、强度大：

• 院校/项目信息多，材料投递状态难追踪；

• 面试题、专业课、英语词汇积累零散，复习无章法；

• 缺乏「模拟抽题」等实战化练习手段；

• 数据若只存在单一平台，存在丢失/不可迁移风险。

因此自研一个「数据可沉淀、功能可扩展、云端+本地双跑」的工作台。

---

三、核心功能（6 大板块）

| 板块 | 核心能力 |

|------|----------|

| 仪表盘 | 汇总统计（院校数、六级分数、DDL 倒计时等） |

| 今日待办 | 任务清单管理 |

| 项目管理 | 5 列看板（夏令营/预推免申请进度）、院校抽屉详情 |

| 面试资料 | 题目增删改 + 列表超 5 条自动折叠 |

| 专业问题 | 自定义分组管理、参考答案/提示/「我的回答」、模拟抽题（随机 5 题 · 每题 2 分钟） |

| 专业英语 | 词汇/短语中英左右对照、句子纵向排列、条目形态自动判断 |

---

四、技术实现

• **前端**：单文件 HTML + CSS + 原生 JavaScript（无框架），响应式布局（含移动端适配）。

• **云端数据层**：WorkBuddy 页面 SDK（`window.__SMART_PAGE__.database`），基于 Promise 契约的 CRUD + 订阅更新；自建 8 张数据表。

• **本地数据层**：`localStorage` 实现等价数据库（8 张表 schema 硬编码，保持 Promise 契约不变）+ `IndexedDB` 存储附件 Blob。

• **附件与导出**：JSZip 一键打包全部附件为 ZIP 下载；JSON 全量备份/恢复（云端、本地格式互通）。

• **测试**：Node.js + jsdom 渲染冒烟测试、交互测试、数据写读回验证。

• **部署**：页面事务流（create → upload → commit → publish）发布公开链接。

---

五、技术难点与解决方案

1. **多列表折叠的通用抽象**：抽取通用 `foldToggleHtml` / `applyFold` 与 `FOLD_LIMIT=5` 折叠规则，一套逻辑复用面试题、专业问题（按分组）、专业英语（按分组）三类列表，避免重复代码。

2. **数据模型设计**：设计 8 张关联表（院校/项目/材料/待办/面试题/分组/专业问题/专业英语），行数据采用扁平结构（字段名即键、`_id` 主键），简化序列化与迁移。

3. **条目形态自动判断**：专业英语条目优先读表内「类型」字段，否则用「结尾标点 + 词数 + 长度」启发式判定句子/词汇/短语，兼顾准确性与历史数据兼容。

4. **字段命名冲突隔离**：材料表与英语表同有「类型」字段，通过独立 `VOCAB_TYPES` 映射表 + 独立 id/text 字段隔离，避免串数据。

5. **历史数据兼容**：专业问题分组管理兼容旧版「分类」字段，平滑迁移存量数据。

6. **一份代码、两套数据层**：把云端 SDK 抽成统一 Promise 接口，本地版用 localStorage/IndexedDB 实现**同契约替换**，业务代码零改动即可「云端在线 / 本地离线」双跑。

7. **测试工程化**：用 jsdom 搭建离线渲染测试环境，覆盖页面渲染、核心交互、数据库写读回三条链路，保证迭代质量。
